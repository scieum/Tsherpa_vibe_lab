# 파이프라인 (pipeline)

```
P0 입력 ─G0─▶ P1 교과서 준비 ─▶ S0 자료 조사 ─GR─▶ R 대조⏸ ─▶ S1 기획 ─G-a─▶ S2 콘텐츠 ─G-b─▶ SA 참고 그림⏸ ─GA─▶ S3 구현 ─G3─▶ V 화면 점검 ──▶ G4 검수⏸ ──▶ zip 묶음 ──▶ 완료(업로드 대기)
  ▲                ▲                  ▲            │
  └── 변수 문제 ───┴── 개념 오류 ─────┴─ 화면 문제 ┘
```

## 단계별 입출력
| 단계 | story-work 번호 | 입력 | 출력 |
|---|---|---|---|
| S0 자료 조사 | 1 | 단원 입력 파일 + inbox/textbook 교과서·지도서 | `00_research.json`: 지도서 성취기준 원문 + 교과서 쪽·용어·탐구 활동·사례 + 지도서 유의점·범위 (모두 쪽 번호) |
| S1 기획 | 1, 2 | 단원 입력 파일 + `00_research.json` | 단원 명세: 성취기준 + 조작 변수 목록(범위·단위) + 공식/데이터 출처 + 템플릿 유형(T_Fixed/T_Floating) + 지울 기능 + 외부 파일(`media`) |
| R 대조 | — | `00_research.json` + `00_input.md` | 다른 점을 사용자에게 질문(기본값 = 교과서) → `00_input.md` 갱신 |
| S2 콘텐츠 | 5, 6 | 단원 명세 + `00_research.json` | 개념 정리 문구 + 퀴즈 문항(정답 포함) |
| SA 참고 그림 | 3 | 단원 명세 + 사용자 선택 | `03_reference.json` (참고 출처·스타일 메모, 그림은 inbox/refs/) — 페이지에는 코드로 그림 |
| S3 구현 | 3, 4 | 단원 명세 + 콘텐츠 + design.md + `templates/unit/<template>.html` | `index.html` (시뮬레이션 로직 포함) + (쓸 때만) `contents/` |
| V 화면 점검 | 7 | `index.html` + `scenarios.json` | 상태별 캡처 (PC·넓은 화면·전체화면·모바일 세로/가로·⋮ 메뉴) |
| S4(G4) 검수 | 7 | `index.html` + 단원 명세 + 콘텐츠 + 캡처 | 판정 결과 + 승인 기록 + 실제 기기·브라우저 확인 → `<폴더명>.zip` |

## 결정 사항
- 순서 원칙: **성취기준 확인 → 교과서·지도서 조사(S0) → 개발(S1~S3)**. 교과서·지도서에 없는 개념·실험을 넣지 않도록 S0 결과를 모든 단계의 근거로 쓴다.
- 순서: 실제 작업(HTML → 개념 정리)과 달리 **콘텐츠(S2) → 구현(S3)** 으로 바꾼다. 문구를 먼저 확정해 HTML 재작업을 줄인다.
- 피그마 시안: 쓰지 않는다. 공식 템플릿 2종(`ref/T_Fixed_260909.html`, `ref/T_Floating_260909.html`)이 디자인 기준이고, 단원마다는 템플릿 유형을 고르고 필요 없는 기능을 지운 뒤 내용만 채운다 (2026-11-12, 제작 안내 PDF).
- 시뮬레이션 로직: S3에 포함한다. 단, S1 단원 명세에 "쓰는 공식 또는 데이터 출처"가 1줄 이상 있어야 S3로 넘어간다.

## 되돌아가는 지점
| 실패 원인 | 돌아갈 단계 |
|---|---|
| 성취기준 원문·교과서 근거 누락, 쪽 번호 없음 | S0 |
| 참고 출처·스타일 메모 없음 | SA |
| `contents/` 밖·절대경로·출처 없는 외부 파일 (N2) | S3 (출처가 없으면 S1 `media`) |
| 템플릿 유형·삭제 기능 신고 오류 (`template`, `removed_features`) | S1 |
| 신고 없이 기능 삭제, 필수 유지 요소 삭제, 🚫 줄 수정 | S3 |
| 폴더 이름에 한글·공백·대문자 | 사용자 (폴더 이름 다시 정하기) |
| 조작 변수 범위·단위 오류 | S1 |
| 개념 오류 (N1), 퀴즈 정답 오류 | S2 |
| 섹션 누락, design.md 위반, 출처 없는 이미지 (N2) | S3 |

- 같은 단계로 3번 돌아가도 통과하지 못하면 멈추고 사용자에게 묻는다.
