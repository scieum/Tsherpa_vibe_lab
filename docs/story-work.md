# 작업 흐름 (story-work)

AI 없이 손으로 단원 페이지 1개를 만들었을 때의 실제 순서.
⏸ = 멈칫한 지점, → 넘김 = 다른 사람에게 넘긴 지점.

## 작업 문장
1. 나는 교과서에서 단원 성취기준을 찾아 정리한다.
2. 나는 시뮬레이션에 들어갈 조작 변수(물질, 입사각)를 정한다. ⏸
3. 나는 피그마로 시안을 뽑는다.
4. 나는 HTML 화면을 만든다.
5. 나는 개념 정리 문구를 쓴다. ⏸
6. 나는 퀴즈 문항을 만든다.
7. 검수자가 개념 오류를 확인한다. → 넘김(검수자)
8. 나는 서버에 업로드한다. → 넘김(담당자)

## 산출물 (명사)
| # | 산출물 |
|---|---|
| 1 | 성취기준 정리 |
| 2 | 조작 변수 목록 |
| 3 | 피그마 시안 |
| 4 | HTML 화면 |
| 5 | 개념 정리 문구 |
| 6 | 퀴즈 문항 |
| 7 | 검수 결과 (개념 오류 유무) |
| 8 | 업로드된 페이지 |

## 게이트 위치 후보 (멈칫)
- G-a: 2번 다음. 조작 변수 확정 여부
- G-b: 5번 다음. 개념 정리 문구 정확성

## 에이전트 경계 후보 (넘김)
- B-1: 6 → 7. 제작 → 검수 (검수자는 당분간 제작자 1인이 겸함)
- B-2: 7 → 8. 검수 → 업로드 담당자

## 하네스 범위
- 1~7번까지. 하네스는 "업로드할 단원 폴더가 준비된 상태"에서 끝난다.
- 8번 서버 업로드는 하네스 밖에서 담당자에게 넘긴다.

※ 게이트 통과 조건은 R5에서 정한다. docs/story-service.md의 N1·N2는 여기 재료가 아니라 R5 판정 기준이다.
